# Especificación HU-03: Listar piezas con filtros

- **Historia:** [HU-03](../historias/HU-03-listar-piezas.md)
- **Estado:** Aprobada
- **Fecha:** 2026-11-12
- **Depende de:** [HU-01](HU-01.md) (catálogo); de [HU-02](HU-02.md) solo se usan los identificadores de serie como texto

## 1. Objetivo

Primer comando real de la CLI: `ali listar`, que muestra las piezas del catálogo con filtros combinables, en texto para leer o en JSON para otras herramientas. La lógica de filtrado y orden vive en el núcleo para que la reutilice el servidor MCP (`listar_piezas`, HU-08). La CLI solo interpreta los argumentos y da formato a la salida.

## 2. Uso

```
ali listar [--contenido <carpeta>] [--serie <id>]... [--sin-clasificar]
           [--estado <estado>]... [--desde <AAAA-MM-DD>] [--hasta <AAAA-MM-DD>] [--json]
```

| Opción | Efecto |
| --- | --- |
| `--contenido`, `-c` | Carpeta de contenido. Si no se indica, se usa la variable de entorno `ALI_CONTENIDO` y, si tampoco existe, la carpeta actual |
| `--serie`, `-s` | Solo piezas de esa serie. Se puede repetir: `-s casos-reales -s notas` |
| `--sin-clasificar` | Solo piezas sin serie. Se puede combinar con `--serie`: muestra las de esas series **más** las sin clasificar |
| `--estado`, `-e` | Solo piezas en ese estado (`idea`, `borrador`, `listo`, `programado`, `publicado`). Se puede repetir |
| `--desde` / `--hasta` | Rango de fechas, ambos extremos incluidos. Se puede indicar solo uno |
| `--json` | Salida en JSON (§5) |
| `--help`, `-h` | Ayuda generada automáticamente, en español |

- **Combinación:** entre filtros distintos se exige que se cumplan todos (Y); entre valores repetidos del mismo filtro basta con uno (O). Ejemplo: `-s a -s b -e listo` → (serie a O serie b) Y estado listo.
- Sin filtros se listan todas las piezas.
- El nombre del ejecutable es `ali` (`AssemblyName` del proyecto `Ali.Cli`). Instalarlo como herramienta global es tarea de HU-09; mientras tanto se ejecuta con `dotnet run --project back/src/Ali.Cli -- listar ...`.

## 3. Fecha de una pieza

La **fecha** de una pieza, para filtrar, ordenar y mostrar, es su `fecha_publicada` si la tiene y, si no, su `fecha_prevista`.

- Una pieza sin ninguna de las dos no tiene fecha. Con `--desde` o `--hasta` queda fuera del resultado.
- Los dos campos originales se conservan en la salida JSON.

## 4. Salida de texto

```
FECHA       ESTADO      SERIE          FICHERO
2026-11-10  publicado   casos-reales   casos/01-agentes.md
2026-11-17  programado  casos-reales   casos/02-memoria.md
2026-11-19  listo       resumen-caso   resumenes/01-agentes.md
—           idea        notas          notas/ideas-sueltas.md
—           —           —              borradores/sin-metadatos.md

5 piezas
```

- **Columnas:** fecha, estado, serie y fichero (ruta relativa). Cada columna se ajusta al valor más largo y se separa con dos espacios. Un valor ausente se muestra como `—`.
- **Orden:** cronológico ascendente; las piezas sin fecha van al final. A igual fecha, o entre las piezas sin fecha, se ordena por fichero.
- **Total:** una línea final con el número de piezas listadas (`1 pieza`, `N piezas`). Si no hay ninguna, solo se muestra `No hay piezas que cumplan los filtros.`
- **Avisos:** los de HU-01 se escriben en la **salida de error** (stderr), después del listado y con el formato `aviso: <fichero>: <motivo>`. Así no se mezclan con el listado y una redirección (`> lista.txt`) guarda solo el listado. Se muestran todos los avisos del catálogo, no solo los de las piezas filtradas, porque hablan del estado de la carpeta.
- La consola usa UTF-8 para que las tildes y la `—` se vean bien en Windows.

## 5. Salida JSON

Un único objeto en la salida estándar, con sangría, en UTF-8 y con los nombres de campo del YAML:

```json
{
  "piezas": [
    {
      "fichero": "casos/01-agentes.md",
      "serie": "casos-reales",
      "estado": "publicado",
      "fecha": "2026-11-10",
      "fecha_prevista": "2026-11-09",
      "fecha_publicada": "2026-11-10",
      "url": "https://www.linkedin.com/pulse/...",
      "depende_de": [],
      "formato": "articulo"
    }
  ],
  "avisos": [
    { "fichero": "x.md", "codigo": "InvalidStatus", "campo": "estado", "motivo": "Estado 'hecho' no válido. ..." }
  ]
}
```

- Las piezas aparecen con los mismos filtros y el mismo orden que en texto.
- Los campos ausentes aparecen como `null`, y `depende_de` como lista vacía, para que el esquema sea siempre el mismo.
- `codigo` usa los códigos de HU-01 (`FrontMatterInvalid`, `InvalidStatus`…), que son identificadores estables.
- Los avisos van **dentro** del JSON, en su propia lista, y no en stderr, porque quien consume el JSON necesita un único documento.

## 6. Errores y códigos de salida

| Caso | Mensaje (stderr) | Código |
| --- | --- | --- |
| Listado correcto, con o sin avisos | — | 0 |
| La carpeta de contenido no existe | `error: No existe la carpeta de contenido: <ruta>` | 1 |
| Estado no válido en `--estado` | `error: Estado 'x' no válido. Valores admitidos: idea, borrador, listo, programado, publicado.` | 1 |
| Fecha no válida en `--desde` / `--hasta` | `error: Fecha 'x' no válida en --desde. Formato esperado: AAAA-MM-DD.` | 1 |
| `--desde` posterior a `--hasta` | `error: La fecha 'desde' (2026-12-01) es posterior a 'hasta' (2026-11-01).` (mensaje del núcleo, el mismo que dará el MCP) | 1 |
| Opción desconocida o mal escrita | Mensaje de System.CommandLine y sugerencia de `--help` | 1 |

## 7. Núcleo

```
PieceQuery  = { Series: string[], IncludeUnclassified: bool, Statuses: PieceStatus[], From: DateOnly?, To: DateOnly? }
PieceFilter.Apply(IEnumerable<Piece>, PieceQuery) → Piece[]   (filtrado y ordenado según §2–§4)
Piece.EffectiveDate                                         (§3)
```

- `PieceQuery` vacía equivale a "sin filtros".
- La validación de `From <= To` está en `PieceQuery`, para que CLI y MCP den el mismo error.

## 8. Dependencias

- **System.CommandLine** en `Ali.Cli`: es la biblioteca oficial de Microsoft para interpretar argumentos. Genera la ayuda y valida opciones, y prepara la CLI para los subcomandos de HU-04, HU-05 y HU-07. Se registra como ADR-0008.
- `System.Text.Json`, incluido en .NET, para la salida JSON.
- Nada nuevo en `Ali.Core`.

## 9. Criterios de aceptación (refinados)

| # | Criterio | Prueba |
| --- | --- | --- |
| CA-1 | Sin filtros se listan todas las piezas | Test del núcleo y de la CLI |
| CA-2 | Filtros por serie (repetible), sin clasificar, estado (repetible) y rango de fechas, combinados con Y entre filtros y O dentro de cada uno | Tests del núcleo, uno por filtro y combinaciones |
| CA-3 | El rango usa la fecha de §3, incluye los extremos y excluye las piezas sin fecha | Tests del núcleo |
| CA-4 | Orden cronológico, sin fecha al final, desempate por fichero | Test del núcleo |
| CA-5 | La salida de texto muestra fecha, estado, serie y fichero alineados, con `—` para los ausentes, y el total | Test de la CLI con salida capturada |
| CA-6 | `--json` produce JSON válido con `piezas` y `avisos`, con los campos de §5 | Test de la CLI que deserializa la salida |
| CA-7 | En texto, los avisos van a stderr y no aparecen en stdout | Test de la CLI |
| CA-8 | Los errores de §6 dan su mensaje y código 1; un listado con avisos da código 0 | Tests de la CLI |
| CA-9 | La carpeta se resuelve en este orden: `--contenido`, después `ALI_CONTENIDO` y por último la carpeta actual | Test de la CLI |

Los tests de la CLI ejecutan el comando en el mismo proceso, con stdout y stderr capturados, sobre carpetas temporales. Van en un proyecto nuevo, `Ali.Cli.Tests`.

## 10. Fuera de alcance

- Mostrar el título, la URL o el formato en la salida de texto (sí van en JSON).
- Filtrar por formato o por texto libre.
- Validar que las series de `--serie` existen en `series.yaml`. Un id que no existe da simplemente cero piezas.
- Paginación, colores y salida en CSV.
- Instalación como herramienta `ali` en el PATH (HU-09).
