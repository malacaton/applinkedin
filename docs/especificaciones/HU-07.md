# Especificación HU-07: Crear una pieza nueva

- **Historia:** [HU-07](../historias/HU-07-crear-pieza.md)
- **Estado:** Aprobada
- **Fecha:** 2026-11-15
- **Decisiones aplicables:** [ADR-0002](../decisiones/0002-ficheros-como-fuente-de-verdad.md)
- **Depende de:** [HU-01](HU-01.md) (formato del bloque), [HU-02](HU-02.md) (series; se amplía), [HU-05](HU-05.md) (primera fecha libre)

## 1. Objetivo

Crear el `.md` de una pieza nueva con su nombre y su bloque YAML correctos, para no tener que recordar la convención. La lógica vive en el núcleo para que la reutilice el MCP (`crear_pieza`, HU-08). La CLI añade `ali crear`.

## 2. Convención de nombres (ampliación del fichero de series)

Se añaden dos campos **opcionales** a cada serie en `series.yaml`. Son retrocompatibles: un fichero de HU-02 sigue siendo válido.

| Campo | Por defecto | Regla |
| --- | --- | --- |
| `carpeta` | El `id` de la serie | Ruta relativa a la carpeta de contenido, con `/`. No puede tener `..`, ser absoluta ni contener segmentos ocultos (`.x`) |
| `fichero` | `{nn}-{titulo}` | Plantilla del nombre, sin `.md`. Debe incluir `{titulo}`. Marcadores admitidos: `{n}`, `{nn}` o `{nnn}` (número de orden sin relleno, o con relleno a 2 o 3 cifras), `{titulo}` y `{fecha}` (fecha prevista `AAAA-MM-DD`; si se usa, la fecha es obligatoria al crear) |

```yaml
series:
  - id: casos-reales
    nombre: Casos reales
    carpeta: casos
    fichero: "{nn}-{titulo}"
    cadencia: { dias: [martes], frecuencia: semanal }
```

Errores nuevos de carga, con el formato de HU-02:

- `Serie 'x', campo 'fichero': debe incluir {titulo}.`
- `Serie 'x', campo 'fichero': marcador '{numero}' desconocido; usa {n}, {nn}, {nnn}, {titulo} o {fecha}.`
- `Serie 'x', campo 'carpeta': debe ser una ruta relativa dentro de la carpeta de contenido.`

## 3. Uso (CLI)

```
ali crear <serie> <titulo> [--contenido <carpeta>] [--series <fichero>]
          [--fecha <fecha> | --fecha-libre [--desde <fecha>]]
          [--formato <texto>] [--depende-de <pieza>]...
```

| Opción | Efecto |
| --- | --- |
| `<serie>`, `<titulo>` | Serie existente y título libre (entre comillas si lleva espacios) |
| `--fecha` | `fecha_prevista` explícita: `AAAA-MM-DD` u `hoy` |
| `--fecha-libre` | Asigna como `fecha_prevista` la primera fecha libre de la serie (HU-05), buscando desde `--desde` (por defecto, `hoy`). No se combina con `--fecha` |
| `--formato` | Valor de `formato` (`articulo`, `post`, `carrusel`…) |
| `--depende-de` | Pieza de la que depende; se puede repetir. Se escribe tal cual en `depende_de` |

**Salida:**

```
Creada casos/05-que-aprendimos-del-rag.md
  serie: casos-reales
  estado: idea
  fecha_prevista: 2026-12-01
```

## 4. Qué se crea

### Nombre

- **Título a texto de fichero (`{titulo}`):**
  - Se pasa a minúsculas y se quitan las tildes y diéresis; la `ñ` pasa a `n`.
  - Cualquier carácter que no sea letra o dígito ASCII se convierte en `-`.
  - Los guiones repetidos se juntan y se quitan los de los extremos.
  - Se recorta a 60 caracteres sin dejar un guion final.
  - Si el resultado queda vacío, es un error: `El título no contiene letras ni dígitos.`
- **Número (`{n}`, `{nn}`, `{nnn}`):**
  - Es el número más alto de las piezas de la serie, más uno; si no hay ninguna, 1.
  - El número de una pieza es el de las cifras con las que empieza su nombre de fichero (`05-x.md` → 5). Las piezas que no empiezan por cifras no cuentan.
  - Cuentan todas las piezas con esa `serie`, en cualquier carpeta y estado.
  - Si el número no cabe en el relleno (`{nn}` con 100), se escribe completo.
- **Ruta:** `<carpeta>/<plantilla resuelta>.md`. Si la carpeta no existe, se crea.

### Contenido

```markdown
---
serie: casos-reales
estado: idea
fecha_prevista: 2026-12-01
formato: articulo
depende_de:
  - casos/04-memoria
---
# Qué aprendimos del RAG
```

- **Campos:** solo se escriben los que tienen valor, en el orden del ejemplo.
- **Cuerpo:** el título va tal cual como encabezado `#`.
- **Codificación:** UTF-8 sin BOM, con saltos `\n`.
- **Comprobación:** como en HU-04, antes de crear el fichero se relee el contenido con el lector de HU-01. El resultado debe dar exactamente los valores pedidos.

### `--fecha-libre`

- **Serie con cadencia:** se toma el primer hueco de HU-05 desde `--desde`.
- **Serie con `despues_de`:** se toma el primer hueco pendiente y, además, se añade su pieza de referencia (`tras`, sin `.md`) a `depende_de` si no estaba ya.
- **Sin huecos:** si no hay ninguno, error `No hay huecos libres para x desde y.`; la pieza no se crea.
- **Serie sin regla:** el error de HU-05.

## 5. Reglas y errores

Se comprueban todas antes de escribir. El fichero se crea con modo "crear nuevo", de forma atómica, así que **nunca se sobrescribe** un fichero existente.

| Caso | Mensaje |
| --- | --- |
| Serie inexistente | El de HU-05 |
| Título vacío o sin letras ni dígitos | `El título no contiene letras ni dígitos.` |
| `--fecha` y `--fecha-libre` a la vez | `Usa --fecha o --fecha-libre, no las dos.` |
| La plantilla usa `{fecha}` y no hay fecha | `La serie 'x' usa {fecha} en el nombre: indica --fecha o --fecha-libre.` |
| Ya existe el fichero | `Ya existe 'casos/05-x.md'; no se sobrescribe.` |
| Fecha inválida | El de HU-04 (`AAAA-MM-DD u hoy`) |

## 7. Criterios de aceptación (refinados)

| # | Criterio | Prueba |
| --- | --- | --- |
| CA-1 | Se crea el `.md` en la carpeta de la serie, con el nombre de la plantilla y un bloque con `serie` y `estado: idea` | Test |
| CA-2 | La numeración sigue a la pieza de número más alto de la serie, en cualquier carpeta; sin piezas, empieza en 1; se respeta el relleno | Tests |
| CA-3 | El título se convierte según §4 (tildes, `ñ`, símbolos, longitud) | Test con casos |
| CA-4 | Si el fichero existe, no se sobrescribe y se informa | Test que compara los bytes del fichero existente |
| CA-5 | `--fecha-libre` asigna el primer hueco de HU-05; en `despues_de` añade la dependencia | Tests |
| CA-6 | Los campos nuevos de `series.yaml` se validan y un fichero de HU-02 sigue cargando igual | Tests del cargador |
| CA-7 | `ali crear` muestra la ruta y los campos y termina con código 0; con error, código 1 y mensaje en stderr | Tests de la CLI |

## 8. Fuera de alcance

- Plantillas de cuerpo por serie o formato (más allá del título).
- Crear varias piezas de una vez.
- Renombrar o renumerar piezas existentes.
- Guardar el título en un campo YAML: el título vive en el encabezado del cuerpo.
