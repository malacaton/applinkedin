# Especificación HU-02: Definir series y cadencias

- **Historia:** [HU-02](../historias/HU-02-series-y-cadencias.md)
- **Estado:** Aprobada
- **Fecha:** 2026-11-12
- **Decisiones aplicables:** [ADR-0002](../decisiones/0002-ficheros-como-fuente-de-verdad.md), [ADR-0007](../decisiones/0007-yamldotnet-para-metadatos.md)

## 1. Objetivo

El núcleo carga un fichero de configuración que describe las **series** y su **cadencia**, valida que sea coherente y expone un modelo que HU-05 (huecos) y HU-06 (validación) usarán para saber cuándo toca publicar. Esta historia no añade comandos de CLI ni herramientas MCP.

## 2. Fichero de series

- Es un fichero **YAML**, el mismo formato que los metadatos de las piezas, legible y editable a mano (ADR-0002).
- La ruta se indica al llamar al núcleo. El nombre recomendado es `series.yaml`, y el manual de HU-09 lo documentará.
- Se lee en UTF-8, con o sin BOM. La carga nunca modifica el fichero.

### Ejemplo

```yaml
series:
  - id: casos-reales
    nombre: Casos reales
    cadencia:
      dias: [martes]
      frecuencia: semanal
      hora: "09:00"

  - id: fundamentos
    nombre: Fundamentos
    cadencia:
      dias: [lunes, jueves]
      frecuencia: quincenal
      desde: 2026-11-02          # semana de referencia para la alternancia
      hora: "08:30"

  - id: resumen-caso
    nombre: Resumen de un caso
    despues_de:
      serie: casos-reales
      dias: 2                    # dos días después de su pieza relacionada

  - id: notas
    nombre: Notas sueltas        # sin cadencia: publicación libre
```

## 3. Campos

### Serie

| Campo | Obligatorio | Regla |
| --- | --- | --- |
| `id` | sí | Minúsculas, dígitos y guiones (`^[a-z0-9]+(-[a-z0-9]+)*$`). Único en el fichero. Es el valor que las piezas ponen en `serie` |
| `nombre` | sí | Texto no vacío |
| `cadencia` | no | Si falta, la publicación es libre |
| `despues_de` | no | Liga las piezas de esta serie a las de otra |

Una serie puede tener `cadencia`, `despues_de`, las dos o ninguna. Si tiene las dos, en HU-05 la fecha la marcará `despues_de` y la cadencia solo se usará para avisar si la fecha resultante no coincide con un día de la cadencia.

### Cadencia

| Campo | Obligatorio | Regla |
| --- | --- | --- |
| `dias` | sí | Un día o una lista no vacía y sin repetidos de días en español: `lunes` … `domingo`. Se aceptan sin tilde (`miercoles`, `sabado`) y sin distinguir mayúsculas |
| `frecuencia` | sí | `semanal` o `quincenal` |
| `desde` | solo si es `quincenal` | Fecha `AAAA-MM-DD`. Su semana, de lunes a domingo, es una semana "de publicación"; desde ahí se alterna |
| `hora` | no | Hora orientativa `HH:mm`, de 24 horas (`09:00`, `18:30`) |

### `despues_de`

| Campo | Obligatorio | Regla |
| --- | --- | --- |
| `serie` | sí | `id` de otra serie que exista en el fichero; no puede ser la propia |
| `dias` | sí | Entero de 1 a 60 |

No se permiten ciclos (A depende de B y B depende de A, directa o indirectamente).

## 4. Contrato

```
SeriesConfigLoader.Load(string path) → SeriesConfig
SeriesConfig = { Series: Series[] }    (orden del fichero; búsqueda por id con Find(id))
Series       = { Id, Name, Cadence?, After? }
Cadence      = { Days: DayOfWeek[], Frequency (Weekly | Biweekly), Anchor: DateOnly?, Time: TimeOnly? }
               Matches(DateOnly date) → bool
SeriesLink   = { SeriesId, Days }
```

- `Cadence.Matches(fecha)` indica si una fecha cae en un día de publicación:
  - **Semanal:** el día de la semana está en `dias`.
  - **Quincenal:** además, la semana de la fecha está a un número par de semanas de la semana de `desde`. Vale también para fechas anteriores a `desde`.
  - Calcular las próximas fechas libres es tarea de HU-05; aquí solo se define la regla.
- **Errores:** si hay cualquier problema, `Load` lanza `SeriesConfigException` con la **lista completa** de errores encontrados, no solo el primero. Cada error indica la **serie** (su `id`, o su posición si no tiene `id` válido), el **campo** (ruta como `cadencia.dias`) y el **motivo**. El mensaje de la excepción los resume en líneas legibles en español.

## 5. Errores

| Caso | Ejemplo de mensaje |
| --- | --- |
| Fichero inexistente o ruta vacía | `No existe el fichero de series: C:\...\series.yaml` |
| YAML mal formado | `YAML no válido en la línea 7, columna 3: ...` |
| Raíz sin la clave `series`, o `series` que no es una lista | `El fichero debe tener una clave 'series' con la lista de series.` |
| Campo obligatorio ausente | `Serie 'casos-reales', campo 'nombre': es obligatorio.` |
| `id` con formato inválido | `Serie n.º 3, campo 'id': 'Casos Reales' no es válido; usa minúsculas, dígitos y guiones.` |
| `id` duplicado | `Serie 'notas', campo 'id': está repetido (series n.º 2 y n.º 5).` |
| Día inválido o repetido | `Serie 'fundamentos', campo 'cadencia.dias': 'juebes' no es un día de la semana.` |
| Frecuencia inválida | `Serie 'x', campo 'cadencia.frecuencia': 'mensual' no es válida; usa semanal o quincenal.` |
| `desde` ausente en quincenal, o fecha inválida | `Serie 'x', campo 'cadencia.desde': es obligatorio con frecuencia quincenal.` |
| Hora inválida | `Serie 'x', campo 'cadencia.hora': '25:00' no es una hora HH:mm válida.` |
| `despues_de.serie` inexistente o la propia | `Serie 'resumen-caso', campo 'despues_de.serie': la serie 'casos' no existe.` |
| `despues_de.dias` fuera de rango | `Serie 'x', campo 'despues_de.dias': debe ser un entero entre 1 y 60.` |
| Ciclo | `Serie 'a', campo 'despues_de.serie': ciclo de dependencias a → b → a.` |
| Campo desconocido | `Serie 'x', campo 'cadencia.frequencia': campo desconocido.` |
| Tipo incorrecto (lista donde va texto, etc.) | `Serie 'x', campo 'nombre': debe ser un texto.` |

Una lista `series` vacía es válida: es una configuración sin series.

## 6. Criterios de aceptación (refinados)

| # | Criterio | Prueba |
| --- | --- | --- |
| CA-1 | El ejemplo de §2 se carga con todos sus campos (ids, nombres, días, frecuencia, `desde`, hora, `despues_de`) | Test |
| CA-2 | Una serie sin cadencia es válida y su `Cadence` es nula | Test |
| CA-3 | `despues_de` se carga y se valida: serie existente, distinta de la propia, días de 1 a 60, sin ciclos | Un test por regla |
| CA-4 | Cada caso de §5 da un error que indica serie, campo y motivo | Un test por caso |
| CA-5 | Si hay varios errores, se informa de todos a la vez | Test con tres errores en series distintas |
| CA-6 | `Matches` es correcto en semanal y en quincenal, incluidas fechas anteriores a `desde` y cambios de año | Tests con fechas concretas |
| CA-7 | Los días se aceptan con o sin tilde y en mayúsculas | Test |
| CA-8 | La carga no modifica el fichero | Bytes y fecha de modificación, antes y después |

## 7. Fuera de alcance

- Festivos y vacaciones (lo dice la historia).
- Calcular huecos (HU-05) y comprobar que la `serie` de cada pieza existe en la configuración (HU-06).
- Editar el fichero de series desde la herramienta.
- Otras frecuencias (mensual, "primer martes de mes"…). El modelo admite añadirlas después sin romper el formato.
- Zona horaria: la hora es solo orientativa y local.

## 8. Decisiones de la revisión

| Pregunta | Decisión |
| --- | --- |
| Campos desconocidos | Son error: el fichero es pequeño y lo escribe una persona, así que una errata no debe pasar inadvertida |
| Frecuencias | `semanal` y `quincenal` en la v1 |
| Rango de `despues_de.dias` | De 1 a 60; sin 0 |
| Varias series en la misma semana | Es lo normal: las series son independientes y pueden coincidir en semana, habitualmente separadas por días. En HU-02 ninguna regla lo impide. Si conviene una separación mínima entre piezas de series distintas, se tratará en HU-05 (huecos) y HU-06 (validación) |

## 9. Ajuste durante la implementación

- `cadencia.dias` acepta también un único día sin lista (`dias: martes`), por comodidad al escribir a mano. Equivale a `dias: [martes]`.
