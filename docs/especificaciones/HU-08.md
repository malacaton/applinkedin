- **Historia:** [HU-08](../historias/HU-08-servidor-mcp.md)
- **Estado:** Aprobada
- **Fecha:** 2026-11-15
- **Decisiones aplicables:**
  - [ADR-0001](../decisiones/0001-stack-tecnologico.md): SDK oficial de MCP para C#.
  - [ADR-0005](../decisiones/0005-ia-fuera-del-nucleo.md)
  - [ADR-0006](../decisiones/0006-aplicacion-local-sin-autenticacion.md)
- **Depende de:** HU-03 a HU-07

## 1. Objetivo

Exponer el núcleo a un asistente de IA mediante un servidor **MCP local por stdio** con cinco herramientas: `listar_piezas`, `buscar_huecos`, `validar_calendario`, `cambiar_estado` y `crear_pieza`.

- **Capa fina:** el servidor no tiene lógica propia; cada herramienta llama al mismo código del núcleo que la CLI.
- **Mismo resultado:** los datos que devuelve son los de `--json` de la CLI.
- **Mismas reglas de escritura:** se aplican las de HU-04 y HU-07.

## 2. Arranque

```
ali-mcp --contenido <carpeta> [--series <fichero>]
```

| Opción | Regla |
| --- | --- |
| `--contenido` | Obligatoria, salvo que esté definida `ALI_CONTENIDO`. A diferencia de la CLI, **no** se usa la carpeta actual: el cliente de IA lanza el servidor desde una carpeta imprevisible |
| `--series` | Opcional. Por defecto, `ALI_SERIES` y, si no está definida, `series.yaml` en la carpeta de contenido (como en la CLI) |

**Comportamiento:**

- **Carpeta de contenido:** se comprueba al arrancar. Si no existe, el servidor escribe `error: No existe la carpeta de contenido: …` en stderr y termina con código 1.
- **Fichero de series:** no se exige al arrancar. Se lee en cada llamada que lo necesita, así que un fichero que falta o tiene errores solo afecta a esas herramientas, que devuelven el error. `listar_piezas` funciona sin él.
- **Datos siempre actuales:** el catálogo y las series se leen en **cada llamada**, sin caché. Si se editan los ficheros a mano mientras el servidor está abierto, la siguiente llamada ya lo ve.
- **Canal de salida:** stdout es exclusivo del protocolo. Cualquier traza o aviso de arranque va a stderr.

## 3. Herramientas

Los nombres de los parámetros son los de la CLI y el YAML, en español. Las fechas se escriben `AAAA-MM-DD` o `hoy`. Cada herramienta lleva una descripción en español y las anotaciones MCP indicadas.

| Herramienta | Parámetros | Devuelve | Anotaciones |
| --- | --- | --- | --- |
| `listar_piezas` | `serie[]?`, `sin_clasificar?`, `estado[]?`, `desde?`, `hasta?` | `{ piezas, avisos }`, como `ali listar --json` | solo lectura, idempotente |
| `buscar_huecos` | `serie`, `desde?` (`hoy`), `cantidad?` (5, de 1 a 100) | `{ serie, desde, huecos, avisos }`, como `ali huecos --json` | solo lectura, idempotente |
| `validar_calendario` | `desde?` (`hoy`), `hasta?` (+28 días), `serie[]?` | `{ desde, hasta, problemas, avisos }`, como `ali validar --json` | solo lectura, idempotente |
| `cambiar_estado` | `fichero`, `estado?`, `fecha_prevista?`, `fecha_publicada?`, `url?` | `{ fichero, cambios: [{ campo, antes, despues }] }`; `cambios` vacío si no había nada que cambiar | escribe, no destructiva, idempotente |
| `crear_pieza` | `serie`, `titulo`, `fecha?`, `fecha_libre?`, `desde?`, `formato?`, `depende_de[]?` | `{ fichero, serie, estado, fecha_prevista, formato, depende_de }` | escribe, no destructiva, no idempotente |

- **Ninguna herramienta borra datos:** `cambiar_estado` solo reescribe el bloque YAML y `crear_pieza` nunca sobrescribe. Por eso todas son "no destructivas".
- **Mundo cerrado:** todas se marcan con `openWorld: false`, porque solo tocan la carpeta local.

## 4. Errores

- **Errores del dato o de la petición:** una serie inexistente, una fecha inválida, un fichero que ya existe o un bloque YAML roto. Se devuelven como **resultado de herramienta con error** (`isError: true`), con el mismo mensaje en español que la CLI, sin el prefijo `error:`. El asistente puede leerlo y corregir.
- **Errores inesperados:** el SDK los devuelve como error genérico, sin detalles internos. El servidor sigue funcionando.

## 5. Código compartido

Para que la CLI y el servidor no dupliquen lógica, pasan al núcleo:

- **Formato JSON:** los documentos de salida (los de `listar`, `huecos`, `validar`, `cambiar_estado` y `crear_pieza`) y las opciones del serializador. Van a `Ali.Core.Output`, que usa `System.Text.Json`, incluido en .NET.
- **Fechas `hoy`:** la lectura de fechas con `hoy` y de estados, con sus mensajes. El nombre de la opción en el mensaje lo pone quien llama: `--desde` en la CLI y `desde` en el MCP.
- **Ubicación de ficheros:** la resolución de carpeta y fichero de series. La CLI tiene una variante que usa la carpeta actual como último recurso y el MCP otra que no.

La salida `--json` de la CLI no cambia. Los tests actuales de la CLI lo garantizan.

## 6. Dependencias (ADR-0009)

- **`ModelContextProtocol` 2.4.0:** SDK oficial de MCP para C#, con licencia MIT y binarios para `net10.0`. Se usa solo en `Ali.Mcp`.
- **`Microsoft.Extensions.Hosting` 10.0.x:** el host genérico que el SDK necesita para el transporte stdio. Se usa solo en `Ali.Mcp`.
- **Núcleo y CLI:** no añaden nada.

## 7. Pruebas

- **Cada herramienta, en el mismo proceso:** se prueba llamando a su método con una carpeta temporal. Los casos son los correctos, los errores (`isError`) y que los datos coincidan con el JSON de la CLI.
- **De extremo a extremo:**
  - Un test arranca `ali-mcp` como proceso y se conecta con el cliente stdio del propio SDK.
  - Comprueba que `tools/list` devuelve las cinco herramientas con descripción y anotaciones.
  - Comprueba que una llamada real funciona.
- **Proyecto:** las pruebas van en un proyecto nuevo, `Ali.Mcp.Tests`.

## 8. Criterios de aceptación (refinados)

| # | Criterio | Prueba |
| --- | --- | --- |
| CA-1 | `tools/list` devuelve las cinco herramientas con descripción en español, parámetros descritos y anotaciones de §3 | Test de extremo a extremo |
| CA-2 | `listar_piezas`, `buscar_huecos` y `validar_calendario` devuelven los mismos datos que `--json` de la CLI | Tests que comparan ambas salidas |
| CA-3 | `cambiar_estado` y `crear_pieza` aplican las reglas de HU-04 y HU-07 (cuerpo intacto, sin sobrescribir…) | Tests |
| CA-4 | Los errores de dato llegan con `isError` y el mensaje en español; el servidor sigue respondiendo | Test |
| CA-5 | Sin carpeta de contenido válida, el servidor no arranca: mensaje en stderr y código 1 | Test de proceso |
| CA-6 | Cada llamada ve los cambios hechos a mano en los ficheros | Test que edita un fichero entre dos llamadas |
| CA-7 | Nada que no sea protocolo sale por stdout | Comprobado en el test de extremo a extremo |

## 9. Fuera de alcance

- Servidor remoto (HTTP), como dice la historia.
- Recursos y prompts MCP: solo herramientas. La skill de ejemplo es HU-10.
- Instalación como herramienta de `dotnet` y configuración de Claude Desktop (HU-09).
- Notificaciones de cambios en los ficheros.
