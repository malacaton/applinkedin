# Especificación HU-05: Buscar huecos libres

- **Historia:** [HU-05](../historias/HU-05-buscar-huecos.md)
- **Estado:** Aprobada
- **Fecha:** 2026-11-15
- **Depende de:** [HU-02](HU-02.md) (series y cadencias), [HU-03](HU-03.md) (catálogo filtrado y CLI)

## 1. Objetivo

Dada una serie y una fecha de inicio, proponer las **N próximas fechas libres**: días que encajan con su regla de publicación y en los que esa serie aún no tiene pieza. El cálculo es determinista y vive en el núcleo para que lo reutilice el MCP (`buscar_huecos`, HU-08). La CLI añade `ali huecos`.

## 2. Uso (CLI)

```
ali huecos <serie> [--contenido <carpeta>] [--series <fichero>]
           [--desde <fecha>] [--cantidad <n>] [--json]
```

| Opción | Efecto |
| --- | --- |
| `<serie>` | `id` de la serie, tal como aparece en el fichero de series |
| `--contenido`, `-c` | Igual que en `listar`: opción, después `ALI_CONTENIDO` y por último la carpeta actual |
| `--series` | Fichero de series. Por defecto, `ALI_SERIES` y, si no está definida, `series.yaml` en la raíz de la carpeta de contenido |
| `--desde` | Primera fecha candidata, incluida: `AAAA-MM-DD` u `hoy`. Por defecto, `hoy` |
| `--cantidad`, `-n` | Número de huecos, de 1 a 100. Por defecto, 5 |
| `--json` | Salida en JSON |

**Salida de texto:**

```
Huecos de casos-reales (los martes, semanal) desde 2026-11-15:

FECHA       DÍA     COINCIDE CON
2026-11-24  martes  —
2026-12-01  martes  fundamentos/03-tokens.md
2026-12-15  martes  —
...
```

- `COINCIDE CON` muestra, solo como información, las piezas de **otras** series con fecha ese mismo día. No bloquea el hueco: varias series pueden coincidir (ver la decisión de HU-02).
- Los avisos del catálogo van a stderr con el formato de `listar`.

**JSON:**

```json
{
  "serie": "casos-reales",
  "desde": "2026-11-15",
  "huecos": [
    { "fecha": "2026-11-24", "dia": "martes", "tras": null, "coincide_con": [], "aviso": null }
  ],
  "avisos": [ ... ]
}
```

## 3. Qué ocupa una fecha

Una fecha está **ocupada** para una serie si al menos una pieza de esa serie cumple todo esto:

- Su estado es `listo`, `programado` o `publicado`, como dice la historia.
- Tiene fecha efectiva (`fecha_publicada` si la hay; si no, `fecha_prevista`), la misma de `listar`.
- Esa fecha es la del hueco.

Las piezas en `idea` o `borrador`, aunque tengan fecha prevista, **no ocupan** (pregunta abierta 1). Tampoco ocupan las piezas sin clasificar ni las de otras series. Las piezas con metadatos inválidos se tratan como en el catálogo: el campo inválido cuenta como ausente y se emite el aviso.

## 4. Cómo se calculan los huecos

### Serie con `cadencia`

- Se recorren los días desde `--desde` en adelante.
- Cada día que cumple `Cadence.Matches` (HU-02) es candidato. Si la serie publica varios días por semana, cada uno es un hueco distinto.
- Se descartan los candidatos ocupados y se devuelven los N primeros.
- La búsqueda siempre termina, porque el número de piezas es finito.

### Serie con `despues_de`

- Su fecha no la marca el calendario, sino la serie de referencia: cada pieza de la serie de referencia que ocupe fecha (§3) pide una pieza de esta serie `dias` días después.
- Ese hueco está **cubierto** si alguna pieza de esta serie, en cualquier estado, la incluye en `depende_de`, con o sin `.md`.
- Los huecos sin cubrir con fecha ≥ `--desde` se devuelven ordenados por fecha y después por la ruta de la pieza de referencia, hasta N. Cada uno indica en `tras` la pieza de la que sale.
- Si además tiene `cadencia`, se mantiene la fecha calculada. Cuando no encaja con la cadencia, el hueco lleva un aviso (`La fecha no coincide con la cadencia de la serie.`), como fijó HU-02.
- Puede haber menos de N huecos. Si no hay ninguno: `No hay huecos pendientes para resumen-caso desde 2026-11-15.`

### Serie sin regla

Si la serie no tiene `cadencia` ni `despues_de`, es un error: `La serie 'notas' no tiene cadencia; no se pueden calcular huecos.`

## 5. Errores

Se escriben en stderr como `error: <motivo>` y el comando termina con código 1.

| Caso | Mensaje |
| --- | --- |
| Serie inexistente | `La serie 'x' no existe en <fichero>. Series disponibles: a, b, c.` |
| Serie sin regla | El de §4 |
| Fichero de series inexistente o inválido | El de HU-02, con todos sus errores |
| Carpeta de contenido inexistente | El de `listar` |
| Fecha inválida | `Fecha 'x' no válida en --desde. Formato esperado: AAAA-MM-DD u hoy.` |
| Cantidad fuera de rango | `La cantidad debe ser un entero entre 1 y 100.` |

## 6. Núcleo

```
SlotFinder.Find(SeriesConfig config, IReadOnlyList<Piece> pieces, string seriesId, DateOnly from, int count) → SlotSearch
SlotSearch = { Series, From, Slots: Slot[] }
Slot       = { Date, After: Piece?, SameDay: Piece[], CadenceMismatch: bool }
SlotSearchException(message)          (serie inexistente o sin regla; cantidad fuera de rango)
```

- No lee ficheros: recibe la configuración y las piezas ya cargadas, para que los tests sean puros y deterministas.
- La CLI resuelve `hoy` con su reloj inyectable (HU-04).

## 7. Criterios de aceptación (refinados)

| # | Criterio | Prueba |
| --- | --- | --- |
| CA-1 | En una serie semanal se devuelven las N próximas fechas de cadencia, con `--desde` incluido | Test del núcleo |
| CA-2 | Las piezas `listo`, `programado` y `publicado` de la serie ocupan su fecha; `idea`, `borrador`, las piezas sin fecha y las de otras series no la ocupan | Test por caso |
| CA-3 | Quincenal y varios días por semana dan los huecos correctos, también al cambiar de año | Tests con fechas concretas |
| CA-4 | `despues_de`: un hueco por pieza de referencia sin cubrir, con su fecha, `tras` y el aviso de cadencia si procede; las cubiertas por `depende_de` no aparecen | Tests |
| CA-5 | Una serie sin regla o inexistente da su error | Tests |
| CA-6 | `COINCIDE CON` lista las piezas de otras series del mismo día sin bloquear el hueco | Test |
| CA-7 | Mismos datos, mismo resultado: los tests no dependen del reloj ni del orden de los ficheros | Test que baraja las piezas |
| CA-8 | `ali huecos` en texto y JSON, con los valores por defecto (`hoy`, 5, `series.yaml`), da código 0; con error, código 1 y mensaje en stderr | Tests de la CLI |

## 8. Fuera de alcance

- Festivos y vacaciones (HU-02).
- Imponer una separación mínima entre series distintas: solo se informa con `COINCIDE CON` (pregunta abierta 2).
- Huecos de todas las series a la vez: se pide de una en una.
- Reservar un hueco o crear la pieza: eso es HU-07.
- Detectar choques, fechas fuera de cadencia o dependencias rotas: eso es HU-06.

## 9. Decisiones de la revisión

| Pregunta | Decisión |
| --- | --- |
| Borradores con fecha prevista | No ocupan; solo `listo`, `programado` y `publicado`, como dice la historia |
| Coincidencias con otras series | Solo informativas (`COINCIDE CON`); no descartan el hueco |
| Fichero de series por defecto | `series.yaml` en la raíz de la carpeta de contenido; se cambia con `--series` o `ALI_SERIES` |
| `--desde` por defecto | `hoy`, incluido |

## 10. Ajustes durante la implementación

- `COINCIDE CON` aplica la misma regla de §3: solo cuentan las piezas de otras series en `listo`, `programado` o `publicado`. Las ideas y borradores fechados de otras series no se muestran.
- El núcleo no conoce la ruta del fichero de series, así que el error de serie inexistente dice `no existe en el fichero de series` en lugar de la ruta. Si el fichero no define ninguna serie: `La serie 'x' no existe: el fichero de series no define ninguna serie.`
- La cabecera de texto describe la regla: `(martes, semanal)`, `(lunes y jueves, quincenal)` o `(2 días después de casos-reales; cadencia miércoles, semanal)`.
- Las columnas `TRAS` y `AVISO` solo aparecen cuando aplican: `TRAS` en series con `despues_de` y `AVISO` si algún hueco lo tiene.
