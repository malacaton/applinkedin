# Plan y tareas HU-04: Cambiar el estado de una pieza

- **Especificación:** [HU-04](../especificaciones/HU-04.md)
- **Fecha:** 2026-11-14

## Diseño técnico

### Núcleo (`Ali.Core.Content`)

| Tipo | Responsabilidad |
| --- | --- |
| `PieceChanges` | Valores pedidos (`null` = no cambiar) y `IsEmpty` |
| `FieldChange` | Campo, valor anterior (o `null`) y valor nuevo, como texto |
| `PieceUpdateResult` | Ruta relativa, pieza antes y después, y cambios aplicados |
| `PieceUpdateException` | Cualquier regla de validación incumplida; el fichero no se ha tocado |
| `PieceUpdater.Update` | Valida, edita el bloque, comprueba el resultado y escribe de forma segura |

**Algoritmo de `Update`:**

1. **Validación sin acceso al fichero:** al menos un campo y una URL `http`/`https` absoluta y sin espacios.
2. **Ruta:** se normaliza `\` a `/` y se añade `.md` si falta. Se rechazan los segmentos `..` y las rutas que salgan de la raíz. Un segmento oculto (`.x`) o un fichero inexistente dan "No existe la pieza".
3. **Lectura:** se lee el fichero entero como bytes y se separa en BOM, líneas del bloque (cada una con su propio salto) y cuerpo. El cuerpo no se decodifica nunca.
4. **Estado actual:** el YAML del bloque se interpreta con `MetadataParser`, igual que en el catálogo. Un bloque sin cerrar, o los avisos `FrontMatterInvalid` y `FrontMatterNotMapping`, se rechazan.
5. **Regla de `publicado`:** si el estado pedido es `publicado`, hace falta la `fecha_publicada` indicada o la que ya tenga la pieza.
6. **Cambios:** se compara cada valor pedido con el actual. Si no hay ninguna diferencia, se devuelve el resultado sin escribir.
7. **Edición por líneas:**
   - Cada campo que cambia sustituye su línea de primer nivel `clave:` y sus continuaciones: líneas sangradas o que empiezan por `-`, y líneas vacías seguidas de una continuación.
   - Si el campo no existe, se añade antes del cierre.
   - Las líneas que no se tocan conservan sus bytes exactos.
   - Los nombres de carpeta y fichero se toman tal como están en disco. En Windows, `File.Move` aplicaría las mayúsculas que escribió el usuario (ver bitácora).
8. **Comprobación:** el contenido nuevo se vuelve a leer con el lector de HU-01. Debe dar un bloque válido con exactamente los valores esperados (los pedidos, y el resto como estaba).
9. **Escritura:** fichero temporal oculto en la misma carpeta (`.nombre.guid.tmp`) y `File.Move` con sobrescritura. Si algo falla, se borra el temporal.

### CLI (`Ali.Cli`)

| Tipo | Responsabilidad |
| --- | --- |
| `StatusCommand` | `ali estado <fichero>` con `-c`, `-e`, `--fecha-prevista`, `--fecha-publicada` y `--url`. Interpreta el estado y las fechas (incluido `hoy`), llama al núcleo y muestra los cambios |
| `CliContext.Today` | Reloj inyectable para `hoy`; por defecto, la fecha local |
